## The committed split

Computed once by `scripts/build_splits.py` and read from
`artifacts/splits/banksim_oot.json` on every run. The boundary is two timestamps, so the
partition is identical whatever subset of rows is loaded.

| | |

| test starts | 2023-05-14 00:00:00 (step 133, inclusive) |
| embargo | 2 days, 0:00:00 |
| target train share | 70% of rows |

**Embargo rationale.** Steps are days and the widest velocity window is seven of them, so a one-day gap is the minimum that stops a test row's features being computed over training rows.

## Data integrity

Counted from the file, not assumed. The loader clamps a non-positive amount to 0.01 and logs the
count rather than dropping the row, because dropping rows silently moves the base rate.

| check | rows | share |
| --- | ---: | ---: |
| amount <= 0 | 52 | 0.008745% |
| self-transfer (src == dst) | 0 | 0.000000% |

No self-transfers, so the realism leash's rule against them costs nothing here.

## Quirks

- Every value is wrapped in literal single quotes; the loader strips them.
- Fraud is category-driven: es_leisure 95%, es_travel 79%, es_sportsandtoys 50%.
- Base rate 1.21% is ~10x PaySim and AMLSim, so operating points do not carry across.
- No device column, as with the other two anchors.

## What it cannot tell us

- Nothing about A2A or UPI rails; it is card-present retail traffic only.
